# OVP — Design History (out-of-artifact)

This file holds the design narrative and editorial history of the Observable Validation Protocol (OVP) spec. It is kept **separate from the spec itself** on purpose: the spec (`OVP_v0.1_OBSERVABLE_VALIDATION_PROTOCOL.md`) must be cold-readable per its own §7/§9 — handed to an independent reader as a stranger would read it, with no design conversation, lineage notes, or rationale supplied out of band. Design narrative embedded *inside* the spec would defeat that gate (this was itself a cold-reader finding). So the "why" lives here; the spec carries only the "what."

## Lineage

OVP abstracts a question the program kept re-deriving informally:
- **RC_v1** — does graph topology `F` add structure beyond pairwise consistency `C`? (measure: a pair-separation rate)
- **CT-v1** — does a novelty term add structure beyond a baseline formula? (measure: an ablation correlation)
- **Dynametrix-HRRR gate** — is a new predictor redundant with an existing one? (measure: an independence correlation)

Each used a *different* operational measure, which is precisely why they are **lineage, not OVP studies**: they motivate OVP and the ledger begins empty (spec §9). The deeper lesson carried forward is CALIB_POSCONTROL's: the discriminating instrument must itself be validated on synthetic ground truth before its verdicts on real candidates are trusted.

The question OVP operationalizes — whether a candidate quantity earns the status of *validated observable* within a given evidence base — is old (Reichenbach, Quine, Cartwright). What is new is the disciplined, falsifiable procedure.

## Revision history

**Draft → working draft (the one-measure / four-verdict episode).** An early draft pinned a single measure (HDG) but declared four verdicts. The first independent cold-reader pass found this structurally impossible: a redundant candidate and a noise candidate both sit at HDG ≈ 0, so one scalar cannot separate them. Two resolutions were weighed:
- *Option 1* — pin a second statistic (baseline-recoverability) and keep four verdicts. Rejected: a second pinned statistic is a second degree of freedom even when pinned, and it would make a three-statistic v0.3 defensible by the same logic. The version mechanism exists to carry that expansion *across* versions, not within one.
- *Option 2* (adopted) — hold strict one-measure-per-version; v0.1 returns **three** verdicts (Validated, Not-Validated, Inconclusive), with the redundant-vs-noise distinction deferred to **v0.2** (= v0.1 + a pinned baseline-recoverability statistic + the four-verdict structure). The cold pass thereby handed v0.2 its design seed.

Control-failure was reclassified from a fourth verdict to a run-invalidating documented condition (you cannot trust any verdict from an instrument that failed its own setup check).

**Second cold-reader pass (assembled-draft read).** A fresh isolated reviewer, given the spec file and nothing else, returned four blocking findings, all accepted and fixed in the spec:
1. *Identity contradiction* — "one measure per version" vs "metric differs across studies" were never reconciled. Fixed by separating the version-fixed **measure form** (HDG) from the study-pinned **instantiation** (concrete metric, estimator/function class, split protocol, cut points), and noting that instantiating the same measure across substrates is not the same as pinning a second measure.
2. *τ_lo unanchored* — "D ≈ 0 → Not-Validated" only holds if τ_lo > 0, which was unstated. Fixed by pinning τ_lo strictly positive.
3. *Self-defeating cold-reader gate* — the artifact contained design narrative (the Drafting note + inline "(review …)" annotations) that the gate forbids the cold reader from seeing. Fixed by moving all design narrative to this file and stripping the inline scaffolding.
4. *By-construction vs 90/100* — a random noise arm cannot be guaranteed below τ_lo every replication. Fixed by pinning the arm's D-*distribution* (expected value + margin) on the correct side; the ≥-of-R bar is the allowance for sampling scatter.

Smaller fixes from the same pass: Arm 3 reworded from "certifies" to "exercises/witnesses" the Inconclusive verdict (a non-gated arm certifies nothing); `R` defined (replications per study; OVP_POSCONTROL_v1 pins R = 100); split-protocol contents specified; and §6's overloaded word "usable" split into a three-rung ladder — **self-validated** (positive control passes) → **operational** (self-validated + ≥3 real ledger verdicts) → **community-validated** (operational + ≥1 externally-authored candidate).

**Third cold-reader pass (external, post-extraction read).** A fresh external reader, given the rewritten spec body alone, returned two blocking findings in the verdict machinery plus three lesser, all accepted and fixed:
1. *Inconclusive had a second, undefined entry route* — "or power was insufficient to place D cleanly" let a study return Inconclusive on non-D grounds, breaking the "partition the real line / read from D" claim and invoking an unpinned power/CI instrument. Fixed: the verdict is now a deterministic function of the single value `D` against the two cut points; the power disjunct is removed; uncertainty is handled by band placement and characterized by the positive control, not by a verdict-time test.
2. *"Discrimination" had no pinned orientation* — log-loss (lower-is-better) was an admitted example metric, which would invert the sign of `D` and break the `τ_lo` guarantee. Fixed: discrimination is pinned higher-is-better; natively lower-is-better metrics are admitted only in negated/skill-score form.
3. *Provenance satisfiability for the first study* — with an empty ledger and different-measure lineage, the first HDG study (OVP_POSCONTROL_v1) had no obvious admissible cut-point source. Fixed: the **separate pre-lock calibration study** bootstrap path is named explicitly.
4. *"Validation/validated" overloaded* — against §6's own "distinct words" boast. Fixed the two sharpest collisions: "validation edge τ_hi" → "upper cut point"; "validation control" → "setup control."
5. *§5 comparability vs §0* — "only verdicts compare" was in mild tension with §0's "a flip is two different questions." Fixed: verdicts compare only as categorical outcomes, each conditional on the row's pinned baseline/metric/estimator.

The reader also confirmed what holds: boundary handling (Inconclusive closed, the two verdicts open) genuinely partitions for the D-based rule; the v0.1/v0.2 scoping, second-statistic-is-a-new-version rule, gated-vs-witness arm logic, and anti-post-hoc provenance reasoning are internally coherent.

**Fourth cold-reader pass (external).** A fresh external reader, spec body alone, returned three local blockers plus two clarity collisions and a scoping note — none architectural; the reader stated that with these fixed it would be "lockable on internal-consistency grounds." All accepted and fixed:
1. *§2(2) simplicity loophole* — "strictly simpler" admitted "an established prior measure the candidate claims to improve upon," which need not be simpler, weakening every "beats baseline" verdict. Fixed by subordinating the established-prior clause to the simplicity bar (eligible only if no more complex than the candidate).
2. *§4 over-claimed Inconclusive coverage* — asserted all three verdicts "fired at least once," but Arm 3 (the only Inconclusive source) is non-gated, so zero landings are permitted. Fixed: Inconclusive is *targeted but not gated*; band-occupancy is reported; zero occupancy is a recorded calibration finding, not a silent pass.
3. *§1 permitted τ_lo = τ_hi* — collapsing the ambiguity band to a measure-zero point, making Inconclusive unreachable. Fixed: strict inequality `τ_lo < τ_hi` required.
4. *"Positive control" double-used* — study-level (OVP_POSCONTROL_v1) vs Arm 1. Fixed: Arm 1 renamed "sensitivity arm"; "positive control" reserved for the study.
5. *"Binary" vs three verdicts* — §0 called the question binary while §3 lists three. Fixed: Inconclusive framed as an *abstention* from the binary, not a third answer.
Scoping note (not a defect): §8 inherits AEPF terms the body never defines. Added a pointer that they are defined in the parent AEPF spec, supplied among the locked artifacts per §7.

Convergence trend across passes: four structural findings → two blockers + three localized → three local blockers + two clarity, none architectural. Defects are shrinking and localizing toward the leaves of the document.

## Pre-committed lock bar (pinned 2026-06-04, before the fifth pass)

The stopping rule for OVP v0.1 was pre-registered **before** the next cold read, so the read's result cannot move it: **the spec locks as v0.1 when an external cold pass returns no finding that falls in the lock-blocker set defined below.** The label "no lock-blocker = lock" is not self-sufficient; the discipline lives in pre-committing *what counts as a blocker*, so the classification is fixed at the moment of reading rather than negotiated after. The cold reader is shown this taxonomy **before** reading the spec and classifies each finding against it as they read.

**Lock-blocker (returns the document to revision; no lock):**
- Internal contradiction (two sections specifying inconsistent things)
- Defect in the operational measure `D`'s definition, threshold/cut-points, or model/function-class pinning
- Defect in the verdict categories (the three v0.1 verdicts; mutual exclusivity; joint exhaustiveness)
- Defect in the convergence-criterion conditions (§6 ladder)
- Defect in the cross-pass §7 specification
- Defect in §4's control-arm constructions or thresholds
- Anything that materially changes what `OVP_POSCONTROL_v1` would test

**Non-blocker (document locks; finding logged for a v0.x revision queue):**
- Wording, clarity, or readability improvement
- v0.2 design suggestion
- Additional example or worked-instance suggestion
- Stylistic inconsistency
- Forward-looking note about future-version capability
- Improved framing of an honest limitation

If the cold pass returns only non-blockers, the spec locks and the non-blockers go into a v0.x revision queue (not folded in before lock, so the locked artifact is exactly the one that was read). If even one lock-blocker is returned, the spec does not lock; it is revised, and earns a fresh pass under this same bar. The fix-author (including the AI collaborator) cannot be the clearing reader.

**Rationale for Option 1 over the alternatives** (recorded so the choice itself is auditable): zero-findings (Option 2) is asymmetric and likely unattainable — a careful cold reader almost always finds *something*, so the bar would equate a disengaged skim with a careful clean read, and would tend to fail on first attempt and become its own moving target. Two-reader concordance (Option 3) is the right bar for first-time validation of a novel instrument, but is wrong-sized for a *confirmatory* pass on an already-cold-reviewed structure where the open question is narrow (does the three-verdict reshape hold together?); §6's own independence note flags the single-operator sourcing constraint, so requiring two readers here costs timeline without proportional gain. Option 1 with a pinned blocker definition is the proportionate, pre-committed choice.

## §7 two-pass interpretation (standing precedent, set at OVP_POSCONTROL_v1)

OVP v0.1 §7 requires "two independent verification passes" before an OVP study locks. The operative interpretation, fixed here so it is not re-derived at each gate (and to be folded into the spec body proper at v0.2, since the v0.1 body is byte-frozen and cannot be edited):

- **Both passes must return no blocker on byte-identical artifacts.** The locked artifact must have cleared two independent inspections of *the same bytes*. The fix-author (including the AI collaborator) has overlapping design context and cannot be either pass.
- **Non-blocker findings queue without folding.** A clean pass with non-blocker notes still counts; the notes go into the study's revision queue and are **not** folded in before lock, precisely so the next pass reviews the same bytes the previous one cleared. They are folded only at the next forced revision cycle.
- **A blocker resets the count to zero.** If a pass returns a blocker, the fix changes the bytes, so the prior clean pass no longer applies — two fresh clean passes on the new bytes are required, not one. No "mostly the same" carry-forward.
- **Implementation-discovered ambiguities are findings.** When the analysis script is built strictly to the pre-reg and the author hits an under-specified choice that affects results, that is a finding equivalent to a cold-reader's: it returns to the pre-reg to be pinned, never silently encoded in code. If it changes the pre-reg bytes, the count resets.
- **Build-and-smoke is a precondition for routing cold passes.** Before an OVP study's pre-reg is routed for its two cold passes, the analysis script must be (a) built strictly to the pre-reg and (b) smoke-tested on a **non-canonical seed** (never the locked seed). This is mandatory, not optional: a class of blocker — couplings between specific estimator behavior and specific construction (e.g., logistic regression's scale-invariance defeating a scale-parameterized arm) — is **invisible to text review** and only appears when the design is executed. Smoke-discovered blockers reset the lock-bar count to zero exactly like text-discovered ones. Routing a pre-reg to cold readers before its script has run a smoke wastes their passes on bytes the script-realization would have forced to change. (Precedent: OVP_POSCONTROL_v1's Arm 3, `C = B + γ·s2`, passed text review but the smoke showed γ could not control HDG under a scale-invariant linear estimator — caught pre-cold-pass, fixed to a noise-attenuated construction.)
- **[Queued for AEPF v1.1 / OVP v0.x] Pre-cold-pass spec↔implementation conformance cross-check.** Build-and-smoke validates that the code *runs correctly*, but it does not catch **spec↔implementation divergences**: cases where the pre-reg and the script disagree about *what is computed* or *what is produced*, each individually internally consistent. Two such divergences in the SST2_OVP_CALIB work were caught only at cold pass, each forcing a byte-changing revision: (1) the **AP panel** pinned in §3 as targeting the rare error class but coded on the majority class (class-asymmetric metric, wrong class — intent ≠ computation); (2) the **bootstrap sensitivity panel** pinned in §3/§11 and the script docstring but **implemented nowhere** (a signed-off output the single run could not produce — a byte-discipline violation at root). Smoke caught neither, because each artifact ran fine in isolation. **Proposed discipline:** before routing cold passes, run a mechanical cross-check that enumerates every (a) pinned **output**, (b) pinned **parameter/mechanism**, and (c) **metric definition** in the pre-reg, and confirms the script produces/honors each one, and conversely that the script computes nothing the pre-reg doesn't pin. This is exactly the class of check that humans and AIs both miss by reading-for-meaning but a checklist catches every time; it belongs alongside build-and-smoke as a pre-cold-pass precondition. **Pattern evidence (updated 2026-06-07): 5 of 5 SST-2 cold-pass byte-changing findings were spec↔impl divergences, not logic bugs** — the AP class mismatch, the bootstrap pinned-but-unimplemented panel, and then three more on the check's **first deployment** as an explicit cold-reader instruction (check F in the SST2_OVP_CALIB brief): promised HDG distributions not persisted (incl. the §6-check-3 null means, unrecoverable under single-execution), an unpinned-but-computed output, and a promised hash living only in transient stdout. The same cycle also produced a worked example of the two-pass bar's value: two independent readers on **byte-identical** artifacts diverged (clean vs 3 blockers) — the second pass caught what a clean first pass missed, which is precisely why one clean pass is not the bar. **Companion lesson — the persistence-contract principle:** under single-execution discipline, anything the one locked run does not persist is unrecoverable without a forbidden re-run; a pre-reg should therefore pin its *exact* output set ("everything needed to audit the run without re-running it, and nothing beyond the pinned set"), and gate-deciding intermediates (e.g., the null means behind a separability check) must be in it.

## Worked example — independent cross-pass corroboration (candidate AEPF v1.1 lesson)

On the OVP_POSCONTROL_v1 **calibration** pre-reg, the two independent cold passes (2026-06-06, no overlapping context) returned the *same* single non-blocker — the §5 "scale-invariant" overstatement (exact only for unregularized logistic; the L2 penalty couples weakly to scale) — and **no other** finding between them, with no verdict divergence. Independent convergence on the identical finding, from readers who shared no context, is the strongest available signal that (a) the finding is real and (b) the document is otherwise tight. This is the §7 cross-pass discipline producing exactly the signal it was designed for, and it is worth carrying into AEPF v1.1 as a named benefit of the two-pass rule: agreement between independent passes is corroboration, and the *content* of any shared non-blocker is high-confidence by construction. (Recorded as a worked example; the calibration study itself proceeds to lock with the finding queued, not folded, per the byte-identity bar above.)

## MILESTONE — SST2_OVP_CALIB: first real-substrate calibration returns MIS-SPECIFIED (2026-06-08), and the exit fires through an unanticipated door

The first OVP calibration on **real data** (tags `sst2-ovp-calib-lock` → `sst2-ovp-calib-result`, after three pre-lock revision cycles and 2/2 clean cold passes on byte-identical artifacts) returned **MIS-SPECIFIED** — the pre-committed exit, honored exactly as locked: no band, no fudge, lock 2 (negation) does not proceed on this calibration. Three durable lessons:

1. **The named failure mode was not the actual one.** The pre-reg anticipated imbalance fattening the null's *positive* tail (band collapse, check 2). Instead the noise null came out **negative in 200/200 replications** (mean −0.240): on a substrate with extreme confidence compression (median B = 0.9995, 84% > 0.99), junk features under the unstandardized L2 logistic don't merely fail to help — they reliably destroy held-out ranking. So `max`-of-95ths returned exactly 0 and **strict positivity (check 1)** failed. Naming a failure mode in advance is good discipline; the protocol must also stay sound when failure arrives through a different door — it did, because the checks are conjunctive and each independently gates.
2. **Pin-parity across substrates is not automatically a virtue.** The "unstandardized features" pin was inherited from the synthetic positive control for comparability; on real compressed confidence scales it is the proximate cause of the strictly-harmful-null geometry. Carrying a pin from a controlled substrate to a real one is itself a design decision that deserves explicit justification per substrate. (The same run's error-class AP panel shows the identical degeneracy — AP noise null 100% ≤ 0 — so an AP-primary re-instantiation is contra-indicated *by the frozen evidence*, not by argument.)
3. **The persistence contract proved itself immediately.** The full per-replication distributions (the revision-3 B1 fix, forced by a cold pass) made the entire post-mortem — null tail shape, compression stats, AP cross-check — auditable from the frozen `sst2_calibration_results.json` without any forbidden re-run. Had the run persisted only the original scalar summaries, the mechanism behind τ_lo = 0 would have been unrecoverable.

Outcome document: `analysis/sst2_negation_ovp/RESULT_SST2_OVP_CALIB.md` — **cleared its citation gate 2026-06-08** (first review pass found 4 reporting-fidelity blockers in the draft — wrong count via lossy formatting, hash transcription, non-pinned percentile, mis-cited source — fixed and re-verified; then 2/2 clean passes with full programmatic recomputation, incl. byte-identical CSV reconstruction). Reporting-layer lesson recorded in the cross-pass record: result documents inherit the same pinned-rule discipline as analysis code. Any continuation (feature decompression, floor-rule revision, larger substrate, or substrate abandonment) is a **new pre-registration**. The §6 ladder is unmoved (no ledger verdict, as pre-registered).

## DOCUMENTED LIMITATION of OVP v0.1 — the `τ_lo > 0` floor rule is structurally incompatible with high-accuracy / tiny-minority-class targets (2026-06-08, SST2_OVP_CALIB_v2 build-and-smoke)

**Finding.** OVP v0.1's cut-point construction sets `τ_lo = max(P95(null-redundant), P95(null-noise))` and requires `τ_lo > 0`. SST2_OVP_CALIB v1 mis-specified via this rule (`τ_lo = 0`); the v2 build-and-smoke established **why, and that it is not substrate-cosmetic.** On the real `(B, y)`, a standardized-feature logistic (v2's pin) moved the noise null from v1's (mean −0.240, P95 −0.086) to (mean −0.140, P95 −0.023) — closer to zero but still 98% negative — and a regularization sweep (`C` from 1.0 to 0.001) showed the null P95 **plateaus around −0.011 and never crosses zero**. The binding constraint is not feature scaling but the **minority (error) class size**: 78 errors, ~39 per 50/50 split. With a minority class that small, adding *any* irrelevant feature to the discriminator adds out-of-sample ranking variance that hurts AUC more often than it helps, so the null HDG distribution sits below zero and **no strictly-positive floor exists** — by construction, not by accident.

**Scope of the limitation (the general statement).** This recurs on **any** target whose minority class is tiny in absolute terms — i.e., any high-accuracy classifier's *correctness* target. It is a methodological limit of the v0.1 floor rule, not a property of SST-2 or of DistilBERT. The protocol does not silently mis-handle such substrates — it returns MIS-SPECIFIED, honestly — but operators should know the rule cannot produce a band there regardless of estimator, so such substrates should be screened out *before* a calibration is locked.

**Named substrate-eligibility criterion for any real OVP candidate study (v0.1).** A substrate/target is eligible for a candidate audit only if its discrimination target has a **substantial minority class**:
1. minority class ≥ ~150–300 examples in absolute terms (per-split minority large enough that a moderately-noisy feature does not reliably hurt held-out ranking) — roughly model accuracy **70–85% on ≥~1000 examples**, or **85–90% on ≥~3000**;
2. **genuine model uncertainty on a meaningful fraction** of examples (not right-on-easy / wrong-on-a-tiny-tail);
3. per-example outputs materialized or cheaply reproducible from a frozen model+data combo.
This is a substrate–instrument compatibility check, the kind mature evaluation frameworks carry — not a flaw, but it must be **checked before lock**, and is now a precondition for selecting OVP's first real ledger substrate.

**Refinement (2026-06-08, from screening Toxic-BERT vs the ChatGPT-detector): the paper criterion is necessary but NOT sufficient — the decisive screen is the empirical standardized-noise-null test.** Screening three substrates with the standardized estimator's noise-null distribution (the v2 mirror) settled it:
- SST-2 (acc 0.911, 78 errors): noise null P95 **−0.086** — fails badly.
- Toxic-BERT (acc 0.945, **277** errors — *passes the ≥150 paper threshold*): noise null P95 **−0.0006**, still 98% ≤ 0 — **fails the floor test anyway.** High accuracy + heavy confidence compression keep junk reliably (just barely) harmful despite the larger absolute minority.
- ChatGPT-detector RoBERTa (acc **0.678**, **644** errors, balanced labels): noise null P95 **+0.026**, only 34% ≤ 0 — **clears the floor**, with the strong meaningful arm at P5 ≈ +0.30 far above. Provisional USABLE BAND.

So the eligibility procedure is: (a) pre-screen cheaply by the paper criterion, then (b) **decisively confirm by running the standardized noise-null smoke and requiring its P95 > 0** before drafting/locking a calibration. Toxic-BERT's 277 errors clearing the count yet failing the empirical test proves the count alone is not enough; model accuracy in the genuinely-uncertain range (≈68%) is what actually moved the null across zero. The empirical noise-null screen is now the gating substrate-eligibility test.

**Status / disposition.** Recorded as a documented limitation of v0.1 (the spec is not changed on the basis of one substrate; revising the floor rule for tiny-minority targets is a possible v0.x item, flagged with the "don't become an arbitrary ε-fudge" caution). **Queued for AEPF v1.1 capture** as a worked example of build-and-smoke catching a *spec-level scope limit* (not just an implementation bug) before a locked run was spent — alongside the AP-class, bootstrap, persistence-contract, and reporting-fidelity lessons. SST2_OVP_CALIB_v2 is **not locked**; per Option B, the program redirects to a criterion-eligible substrate rather than running v2 to a near-certain MIS-SPECIFIED (the smoke, validated against v1's locked null and a regularization sweep, is already design-level evidence under the build-and-smoke discipline).

## DISCIPLINE ADDITION — approximation qualifiers must be encoded as explicit tolerances (2026-06-08, DETECTOR_OVP_CALIB build-and-smoke)

**The latent bug.** The calibration separability check 3 required "both nulls have mean HDG **≤ ~0**" (pre-reg prose, with the tilde). The SST-2 scripts encoded this as `mean ≤ 1e-9` — i.e., strictly ≤ 0. On every substrate tested through SST-2 the noise null sat far below zero (junk reliably hurts on tiny-minority targets), so `≤ 1e-9` passed trivially and the divergence was invisible. The **first build-and-smoke on an eligible substrate** (ChatGPT-detector, where the noise null is centered at ~0 *by construction* — that centering is what makes `τ_lo > 0` possible) exposed it: the noise null's 200-rep sample mean was +0.0027, a near-zero number whose **sign is sampling noise**, and the strict bound would have returned MIS-SPECIFIED on that technicality — a false negative driven by the encoding, not the data.

**LOAD-BEARING CONFIRMATION (the locked run, not theory).** On the DETECTOR_OVP_CALIB locked single run the noise null's mean came out **+0.0024 — positive**. Under the strict `≤ 1e-9` encoding that survived into the SST-2 v2 script, check 3 would have rejected the otherwise-clean band as a **false MIS-SPECIFIED, on the sign of sampling noise**, on a single-execution run that cannot be re-run. The `ε_null = δ` correction (caught at build-and-smoke that same morning) was therefore the **difference between a usable band and a false negative on the milestone run** — not a hypothetical tidy-up. This is one of the cleanest worked examples in the AEPF v1.1 capture queue: a latent encoding bug, invisible until an *eligible* substrate let it manifest, caught by build-and-smoke, with the fix proven load-bearing on the very next locked run. (Counterfactual recorded explicitly: strict-encoding verdict would have been MIS-SPECIFIED; corrected-encoding verdict was USABLE BAND; the data were identical.)

**The generic rule (now standing discipline).** *Spec/pre-reg text containing an approximation qualifier (`≈`, `~`, "approximately", "about") must be encoded with an **explicit tolerance**, never as strict equality/inequality. The tolerance must be an **already-pinned constant** where one applies, not a freely-chosen number, so the encoding cannot be tuned to an outcome.* Here: "≤ ~0" → `≤ ε_null` with `ε_null = δ` (the existing decision margin), **one-sided** (a legitimately-negative null still passes — junk *hurting* is a real substrate property, not a generator bug). This is a fourth distinct class of build-and-smoke catch, after Arm-3 scale-invariance, the AP error-class mismatch, and the bootstrap pinned-but-unimplemented — and the only one that required an *eligible* substrate to surface. The correction is study-level (the separability checks are the operator's instantiation of spec §1's external-cut-point requirement, not spec text), so no OVP spec change; SST-2's locked verdicts are unaffected (both failed check 1, not check 3). Queued for AEPF v1.1 capture.

## OVP v0.2 DESIGN SEED — the Descriptor Justification Layer (candidate generation, recorded not built; 2026-06-08)

**Motivation.** Auditing is now turnkey; the scarce resource is *candidates worth a single locked execution*. The first three real candidates (`truncated`, `text_length`, `predicted_prob_ai`) were generated from **availability** — cheap, interpretable, materializable — not from a theory of failure. That was the right way to bootstrap the ledger, but a mature program generates candidates from **mechanism**: failure mechanism → observable consequence → descriptor candidate → audit, not interesting-variable → audit. This entry seeds a v0.2 discipline layer **upstream of the audit** that formalizes candidate generation without taxing OVP's core value (the locked record is trustworthy).

**The one principle that must not be violated: mechanism is a *locked disclosure*, NOT an *admission gate*.** A compelling mechanism story is exactly what humans over-trust, and OVP exists because plausible stories keep failing on held-out data (`truncated`'s information-loss story → Inconclusive; RC-v1's representational-instability story → null). If a persuasive mechanism were required to *enter*, the ledger would fill with survivorship and lose the null distribution — we'd never learn what a plausible-but-empty descriptor looks like on the substrate. So **surface descriptors remain first-class** (admitted, audited, used as controls and ledger calibration); every candidate merely *states* its mechanism (or honestly "none — surface control"), pre-committed and cross-passed.

**The Descriptor Justification Layer (locked per candidate, before lock; cross-passed like any pinned element):**

1. **Mechanism disclosure (not gated).** The proposed failure mechanism the descriptor targets — or an explicit "none; surface control."
2. **Baseline-blindness argument.** Why baseline `B` should *miss* this — the critical question. This is an **upgrade of the §2.5 Ancestry Statement from *structural* ("B is a simpler function of C") to *mechanistic* ("here is the failure pathway and why B is blind to it")** — folded into existing locked machinery, not a new unreviewed prose section.
3. **Dual (triple) interpretation, pre-committed and locked** — the strongest anti-HARKing device; it removes post-hoc rescue language. Example form:
   - *If Validated:* X adds information beyond B under this target.
   - *If Not-Validated:* X does not add enough information beyond B under this target — **do NOT reinterpret as "wrong substrate" unless pre-specified.**
   - *If Inconclusive:* X sits in the decision band; no legitimacy claim.
   (Worked precedent: `predicted_prob_ai`'s post-fold pre-commitment — "Inconclusive ⇒ no slope-asymmetry, does not rule out intercept" — was *honored* by the 14-point intercept gap rather than spun.)
4. **Paired surface foil (when possible).** The cheap dumb proxy that should come back *negative* if the mechanism is real — the disconfirming control (e.g. if "perturbation disagreement" Validates, does raw "response-length variance" Validate too?). Makes the ledger self-diagnosing against secretly-tracking length/truncation/class-imbalance/confidence artifacts.
5. **Target-fit check (the Class-C guard).** OVP as instantiated tests one question: *does X add incremental gain over B at predicting correctness?* **Organizational / system-state descriptors** (graph fragmentation, equivalence-closure failure, manifold/stability coherence — the original synchronization intuition) are about *summarizing regime*, not predicting correctness. A good order parameter (e.g. Kuramoto `r`) earned its place by predicting a *dynamical transition*, never by beating a baseline at a correctness target. Forcing such descriptors through the reliability gate would generate a string of nulls that look like "the descriptors are empty" when the real fact is "the instrument asked the wrong question." So each candidate must **justify that the correctness target is the right one for it** — and Class-C descriptors may need a *different target* (predictive of a regime transition / downstream behavioral break) before they belong in an audit at all. **This is the one way the program could now fool itself; naming it before the framework hardens around the reliability target.**

**Resolution kept explicitly OPEN (do not collapse into v0.2).** The answer for Class-C is *not* "force it through the v0.1 reliability gate." It is one of: **(a)** a different OVP *version* with a regime-transition / behavioral-break target instead of a correctness target; or **(b)** a *parallel instrument* entirely (correctness-of-an-observable is one question; characterization-of-system-state is another — possibly not an OVP question at all). v0.2 is the redundant-vs-noise split on the *correctness* target; the Class-C target question is a separate, later, deliberately-unresolved branch. Recording it open is the honest move — the same restraint as declining to over-specify v0.2 before it is built.

**Candidate taxonomy (informal, for focus not gating).** Class A — surface (length, truncation, confidence): cheap, mostly fail, kept as controls. Class B — mechanistic (perturbation disagreement, self-consistency variance, evidence–answer divergence): from an explicit failure theory; the near-term ledger-building sweet spot. Class C — organizational (fragmentation, closure failure, stability-under-perturbation): the program's distinctive contribution and original intuition, but subject to the §5 target-fit guard and likely needing instrument maturity (nonlinear estimators, v0.2's redundant-vs-noise split, a non-correctness target) first.

**Status.** Recorded as a v0.2 design seed; v0.1 is unchanged and its operational ledger stands. The first candidate naturally generated under this layer is the `[B, pred]` intercept-shaped study the direction verdict's diagnostic pointed at — a good first test of the discipline (it has a real mechanism: the measured 14-point intercept asymmetry; a clean baseline-blindness argument: `[B,p]` provably can't represent pure-intercept shift; a natural surface foil; and the correctness target *is* right for it). It is **not** generated from availability — it is generated from the failure structure the ledger itself surfaced. That is the pivot this layer is meant to make routine.

## DISCIPLINE PRINCIPLE — program-evolution changes get the same discipline as artifacts

Proposed *refinements to the framework itself* (new disciplines, candidate-generation rules, spec changes) are subject to the same treatment as locked artifacts: the proposal is adversarially tested for hidden failure modes **before** it hardens; a passing critique lands it as a **recorded design seed**, not a same-day bolt-on to the locked spec; and v0.1 stays untouched while the idea matures. (Worked instance: the Descriptor Justification Layer above — proposed, then critiqued for a survivorship-bias failure mode (mechanism-as-gate), then recorded as a v0.2 seed rather than spec-grafted, with the Class-C target question deliberately left open.) The point is structural: the framework must be willing to apply its own no-premature-hardening, disclose-don't-assert discipline *to its own evolution*, or the locked record's trustworthiness erodes from the top down rather than from a bad verdict.

## OVP v0.2 DESIGN SEED — sealed-run self-guard for judge scripts (recorded not built; 2026-06-10, from DETECTOR_PREDCLASS_OVP cold pass #1)

**The catch (documented motivation).** Cold pass #1 on `DETECTOR_PREDCLASS_OVP` (2026-06-10) identified that every invocation of `judge_*.py` computes the sealed verdict (the HDG-beyond-baseline) in memory and — under the default `--out` — writes a result file. Non-canonical `--seed/--reps` print a WARN and *still* compute the real value; there is no smoke mode in the judge itself (the smoke is a separate synthetic harness). So the no-peeking seal on a *real candidate* run rests entirely on **operator discipline + WARN text**: an idle pre-lock "does it even run?" invocation would both peek and emit a result. Not a violation of any v0.1 gate (the cold reader cleared all five charges), and the cold reader correctly *declined to execute the script* precisely so as not to break the seal — but a residual hazard that lives in discipline rather than in structure, unlike every other guard in the judge (hash-guarded inheritance, runtime cut-point assert, 3-way revision identity).

**Decision: NOT retrofitted to #1–#4; scoped to the v0.2 standard judge template.** Four reasons, the fourth load-bearing: (1) it is the *same* hazard #1–#3 already shipped with — singling out #4 creates asymmetry without retiring the hazard on the studies that carry it; (2) a self-guard introduces a **new class of failure modes** (git unavailable, tag-name conventions, fresh-clone-before-tags-pulled, tarball/CI checkout without git) each needing its own handling and review, replacing the simple mental model both cold passes cleared with a more complex one that would require **re-routing both cold passes** on the guarded artifact — a full revision cycle to add a mechanism not yet validated as the right one among several; (3) the right scope is **template-level**: one review of the standard judge template, applied uniformly to #1–#4 (and counting) at once, rather than four independent retrofit cycles; (4) **the program-evolution principle above** — a self-guard is template-level discipline, not a single-artifact fix, so bolting it onto #4 alone would repeat exactly the category error that keeping the Descriptor Justification Layer out of v0.1's locked spec avoided. The discipline-applies-to-the-discipline lesson is what catches this asymmetry.

**Candidate mechanisms to evaluate when the template is built (tradeoffs, not yet chosen):** (a) **lock-tag git check** — refuse to compute unless the study's signed lock tag exists and points at the script's own commit (strongest seal; heaviest git coupling); (b) **env-var gate** set by the lock procedure (no git dependency; weaker — env is easy to set by accident); (c) **`lock_status` sentinel file** committed at lock (in-repo, git-light; needs its own integrity story); (d) **output-file-exists refusal** (cheap guard against silent re-run/overwrite; does *not* prevent the in-memory peek, so partial). Likely a composition (e.g. tag-check as primary with a clear non-git fallback).

**Status.** Hazard named, scoped to the right level, and not forgotten. v0.1 and #1–#4's seals are unchanged (they hold on operator discipline as before). When the v0.2 standard judge template lands, the self-guard is reviewed once and applied to all existing judge scripts in a single template-level pass — that is the correct place to absorb the cold-pass cost of adding the guard.

## OVP v0.2 LESSON — best-effort artifacts lock against ACCURACY OF CLAIM, not absence of all possible failures (2026-06-10, from the v0.2 template cold-pass-A arc)

**Origin.** The v0.2 reference template's cold-pass-A review ran five executing readers (rev1→rev6). Findings walked from a *demonstrated wrong-compute* (reader #1: H1 covered only the judge, not imported sealed-path modules), through *trusted-not-derived* attestation fields (readers #2/#3: grade, then temporal, then `.gitattributes` coverage), to the *inherent limit of in-process IO sandboxing* (readers #4/#5: `os.system` then `os.spawnv` escaping the closed-world denylist). The architecture never moved; each fix tightened a real claim. Reader #5's finding forced the rule below: it was correctly a blocker, but **because the artifact *overstated* its coverage** (a dead `os.spawnv` denylist string; a false "`ctypes dlopen` routes through `open`" claim) — not because a disclosed limit had another instance.

**The lesson.** Lock-discipline protects the **integrity of what the artifact claims**, not the impossible standard of zero residual failure. A *best-effort* component (one that explicitly discloses it cannot catch all cases — here, the closed-world spawn/network/C-level denylist) admits demonstrable leaks *within its disclosed residual* by definition. Requiring "two readers find literally nothing" of such an artifact demands what it never claimed and the platform can't support — a category error masquerading as strictness.

**The locked bar for any best-effort component (the reset/fold rule, auditable):**
A cold-pass finding **RESETS the count** iff it:
- **(a)** falsifies a **provable guarantee** in the artifact's *positive enumeration* (e.g. the git-identity self-guard's fail-closed behavior, the `open` allowlist, the input-hash/output-exists chain, the attestation's derive-never-trust invariant); **OR**
- **(b)** demonstrates a gap that **should have been disclosed** under reasonable documentation standards but wasn't — i.e. the disclosure section is **too narrow**, or the positive enumeration advertises coverage that isn't delivered (reader #5's `os.spawnv`/`dlopen`).

A finding **FOLDS without resetting** iff it is:
- **(c)** a new **instance of a correctly-disclosed best-effort limit** — the disclosure already covers the *class* conceptually (a future `os.posix_spawn` variant or another C-level `fopen` path, all covered by the "denylist cannot be exhaustive; external sandbox is the real closure" disclaimer). Record it as confirmation that the disclosed limit exists; add the entry if cheap; do **not** reset.

**The judgment lives in (b)** and is auditable: read the disclosure section, ask whether the finding is a class the disclosure covers *conceptually*. Reader #5's `os.spawnv` was a (b) failure because the artifact specifically claimed spawn-*family* coverage and listed a dead string; a future reader's `posix_spawn` variant is a (c) case because the C-level/denylist-non-exhaustive disclaimer covers it conceptually.

**Precedent.** This is the standard for **every** future best-effort component the program produces (the smoke-harness closed-world surface; any self-guard that ends up with disclosed residuals; future RTVP instruments with disclosed measurement limits). Lock against *accuracy of claim*; reset on a false claim or too-narrow disclosure; fold on a correctly-disclosed residual instance. Adopted for the v0.2 template's remaining two cold passes against rev6.

## RESOLVED — re-route-depth taxonomy: Tier B RETIRED; the middle tier is empty (2026-06-10, independent decision pass)

The re-route-depth seed asked: is there a principled middle tier (cheaper than full re-route) for substantive-but-narrow folds? **Answer: NO — Tier B is retired, because its target population is empty.** (Full ruling in `OVP_REROUTE_DEPTH_REVIEW.md` §7.)

**The standing forward rule (codifies the seed's answer):**
- **Substantive fold → full re-route (warm + two cold) is the standing default.** No middle tier.
- **The bifurcation that dissolves the apparent need for one:** a substantive-but-narrow fold is exactly one of two things — **non-false imprecision → QUEUE it, do NOT fold pre-lock** (non-blockers go to the v0.x queue so the locked artifact is exactly what was read; pre-lock folding here is an unforced byte-identity violation); or **false / integrity-critical → full re-route** (the only reason to fold a non-gating finding pre-lock, and exactly where a second independent reader earns its keep — verdict-#3, CP2-N1). The middle has no occupants.
- **Why no cheap test rescues it:** the action-invariance condition relocates the leak (whoever enumerates the outcome set controls the test; and it misses meaning-changes whose action-consequences are *future*). Precision-vs-meaning is a continuum, gameable by re-description unless anchored to an independently-fixed complete outcome set — which is the expensive second-reader work itself. Risk-proportionality also forbids it: one pass on the freshly-changed delta applies the weakest coverage to the highest-risk region.

**Two keepers from the pass (forward improvements, not new tiers):**
- **Add a mechanical ripple / spec↔impl conformance cross-check to Tier C** — cheap, deterministic, catches the *enumerable* divergence class (supplements, never substitutes for, the semantic second cold read).
- **Tighten Tier A** (the prescribed-editorial-fix case) beyond "a downstream pass exists" to: the downstream pass is independent + blocker-powered + scoped to re-read the *changed bytes* + before this artifact's own lock + treats post-fold bytes as fresh (no carry-forward); **and** the downstream reader independently confirms both that applied bytes match what was prescribed *and* that "verbatim" was true (no smuggled meaning). Then Tier A = "defer a genuinely-editorial fold's verification to an already-scheduled full independent pass on the changed bytes before lock" — coherent and free.

This closes the re-route-depth thread. The seed's value was naming the question and forcing the bifurcation that shows the middle is empty — not producing a tier.
